# 维护指南

本文件面向项目维护者，补充数据行为、发布流程与现有运维边界。项目介绍和启动方式见 [README](../README.md)。

## 数据加载与缓存

- 单次请求超时为 30 秒，最多尝试三次；鉴权与业务错误直接失败。
- 分页以服务端 `total` 为准，检查重复页和缺失页，避免用不完整数据替换页面。
- 总览的四个数据集全部成功后才更新快照；失败时保留已有数据，并显示异常或缓存状态。
- 缓存按工厂、版本及 30 分钟有效期校验，同时保存待办与上月统计所需的记录。
- 工厂、月份和趋势请求使用序列校验，过期响应不得覆盖当前选择。

## 业务统计口径

现有代码保留以下统计规则，维护时应先与 QMS 官方业务口径对账，避免仅根据字段名称统一算法。

| 项目 | 当前行为 |
| --- | --- |
| 主要合格率 KPI | 合格批次 / 已判定批次；已判定批次包括合格、退货和特采 |
| 部分供应商排名图 | （全部批次 − 退货 − 特采）/ 全部批次；进行中的批次包含在分母中 |
| 季度 / 年度筛选 | 滚动 3 个月 / 12 个月 |
| Pareto / DPPM | 上游缺少所需字段时显示空状态 |

大工厂跨季度、跨年度查询仍需拉取明细，耗时受数据量与上游响应速度影响。服务器端汇总能力及 Worker 访问控制策略应单独评估。

## 大屏维护

供应商大屏使用视口高度分配布局行，下方三张卡片等高，风险列表在区域内部滚动。修改布局时，应同时验证空数据、少量数据和大量风险记录，避免恢复为由内容决定页面高度。

来料大屏按全部筛选任务连续循环，末条接回首条，速度为 72 像素/秒，不显示分页或行分隔线。仅渲染视口所需行数与两行缓冲，使用固定 44px 行高及 `tbody` 的亚像素位移；跨行时更新可见窗口，避免逐帧读取布局。定时刷新按当前单号保留滚动位置，筛选或排序时重新开始。悬停与页面隐藏时暂停，退出时清理监听器与动画任务；系统启用“减少动态效果”时停止自动滚动，提供完整列表供手动查看。普通质量总览仍保留每页 20 条的手动分页。

导航仅保留质量总览和供应商质量，旧 `#tasks` 地址重定向到质量总览。顶部和大屏控制栏均使用可展开语言菜单，选择语言、点击外部或按 Escape 后收起。

外观主题由 `assets/theme.js` 和 `assets/theme.css` 管理。默认经典，液态玻璃按需开启；`iqc_theme` 仅保存 `classic` 或 `glass`，存储不可用时仍可切换。主题在页面绘制前恢复，切换不会重新请求数据或重建滚动器。普通卡片使用静态背景模糊，大屏卡片不使用模糊；不支持背景模糊或要求减少透明效果时使用更实的卡片底色。发布白名单包含这两个主题文件。

新增界面文案应接入现有翻译机制，覆盖中文、英文、泰文及中泰双语；不得通过替换业务字段值实现界面翻译。

## 发布流程

1. 在独立分支完成变更并提交 Pull Request。
2. 确认 CI 通过；涉及界面时完成浏览器验证。
3. 合并到 `main`，由 `Deploy Pages` 工作流检查、测试并构建 `dist/`。
4. 确认 `build` 和 `deploy` 作业成功，检查生产域名、静态资源和 QMS 同步状态。

GitHub Pages 使用 GitHub Actions 发布，`github-pages` 环境允许 `main` 部署。`gh-pages` 仅保留旧部署历史，不再作为开发或发布源。构建产物采用文件白名单，不包含测试入口、维护文档或本地设置。

不要仅覆盖 `index.html`，否则可能遗漏或混用其依赖的脚本和样式。

### 版本回退

定位引入问题的提交，在独立分支使用 `git revert` 创建反向提交，经测试和 PR 合并后重新部署。回退合并提交时，应先核对父提交关系，再选择正确的主线父提交。

不使用强制推送、历史覆盖或远程分支删除作为常规发布与回退手段。

## 凭证与环境配置

QMS 认证由独立部署的 Cloudflare Worker 完成。前端只包含查询所需的公开接口地址与工厂配置，不应接收或保存 QMS 登录密码。Worker 代码不在本仓库内，维护代理时需单独记录服务版本与配置变更。

`.env`、`.dev.vars` 等本地配置已加入忽略规则。不得将账号密码、令牌、真实检验数据导出文件或未脱敏截图提交到仓库。
